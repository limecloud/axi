# AXI：面向 Agent 的操作界面

AXI（Agent eXperience Interface）描述产品如何让 Agent **找到能力、定位对象、执行操作、观察结果，并在中断后恢复**。人类界面与 Agent 界面共享业务对象、权限、副作用和状态。

例如，“审批这份文档”不应要求 Agent 先浏览所有菜单、猜测同名按钮、反复截图，最后在提交超时后重新审批。产品可以提供小型用途索引、精确合同、明确的文档引用，以及原操作恢复入口；需要判断文档内容时仍保留阅读和人工决定。

!!! info "规范状态"
    当前版本为 **0.2.1 草案**，尚无稳定版本。它是独立设计提案，不具有行业标准地位，也不是其他同名项目的官方规范。规则和 Schema 可用于试验接入；符合性必须附上具体实现和任务证据。

## AXI 包含什么

**核心合同**定义能力目录、动作描述、范围化对象、结果与错误、版本和安全要求。**可选能力**覆盖分页、只读批量、等待、取消和扩展。**绑定指南**说明如何在 CLI、MCP 和浏览器中保留这些语义。

本仓库提供版本化 JSON Schema、正反例夹具、本地参考提供方和文档测试。参考提供方只演示文档审批，不构成可部署的身份系统、MCP 服务或浏览器宿主。

## 与现有协议的关系

AXI 不定义新的网络传输、模型运行时或通用授权协议。CLI 可以承载 AXI JSON；MCP 可以暴露带有这些语义的工具；Skills 提供方法，插件组合与分发组件，MCP Apps 提供会话内的交互视图，网页和 DSH 等宿主也可经适配加入。支持某个载体不自动证明目标任务可用。

正文是自足的实现合同。外部来源集中在[参考资料](references.md)，产品自己的路径、上线记录和测试数据保留在其采用清单中。
