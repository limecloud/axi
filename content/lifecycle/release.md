# 测试、发布与回读

发布交付的是可安装、可连接、可发现并能完成明确任务的候选，而不是某个包上传成功。包、服务和 UI 可以独立发布，但必须声明其组合兼容性。

## 发布候选

候选包含精确源码/制品摘要、原生包清单、能力目录、动作合同、方法资源、可选 UI、身份配置接口、兼容矩阵和测试证据。凭据不进入制品、普通配置导出或审核截图。

```mermaid
flowchart LR
  S[领域能力与单一维护源] --> B[构建原生包、合同、方法与 UI]
  B --> C[静态引用、Schema 与安全检查]
  C --> I[隔离安装和鉴权恢复]
  I --> T[正式宿主任务、降级和性能]
  T --> R[冻结候选与兼容矩阵]
  R --> A[按渠道要求审核与获准发布]
  A --> P[发布精确制品及远程服务]
  P --> V[从远端重新获取并回读]
  V --> H[新会话发现和目标任务验收]
```

## 分层门禁

| 门禁 | 验证内容 | 证据不能扩大为 |
| --- | --- | --- |
| 静态合同 | Schema、索引、引用、摘要、原生清单 | 真实授权通过 |
| 行为 | CAS、幂等、失权、未知、取消和部分失败 | 所有下游已正确 |
| 干净安装 | 依赖、启动、方法和工具发现 | 旧用户升级无风险 |
| 身份 | 连接、拒绝、过期、刷新、切换、撤销 | 所有业务对象获权 |
| 目标宿主 | 实际调用、UI、降级和接管 | 其他宿主兼容 |
| 远端回读 | 实际包/资源版本、服务合同和任务 | 源码存在即已上线 |

## 渠道差异

公共插件目录、企业工作区、仓库 marketplace、CLI 包仓库、远程 MCP 和浏览器扩展各有审核、分发及撤回规则。复用原生渠道；AXI 不授权绕过平台审核，也不定义统一的发布命令。

远程服务变更应重新扫描实际工具和行为；插件包不变也要检查合同漂移。App 静态资源与服务端工具更新分别核对，避免缓存中的旧视图发出不兼容写入。

## 发布完成判据

记录目标渠道、实际可获取版本、启用状态、连接、精确能力修订、真实任务和产物。排队、审核通过、HTTP 201、镜像推送或页面能打开都只能证明相应阶段。

失败时保留脱敏日志与精确候选，定位原因后修复；不要反复重跑或换操作键碰运气。回退计划保留原操作恢复和身份撤销能力。
