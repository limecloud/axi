# 排障

先判断失败发生在发现、定位、执行、观察还是绑定连接层，再处理具体原因。不要用反复重试掩盖不匹配合同。

| 现象 | 先检查 | 处理 |
| --- | --- | --- |
| Agent 总在错的页面找按钮 | 当前对象与命名区域是否可读 | 补精确任务路由和局部定位，不增加坐标提示 |
| 同名按钮误点 | 当前对话框、所属资源、匹配数 | 限定区域，歧义时消歧 |
| 每轮重复列出所有能力 | 合同缓存、版本与用途索引 | 窄发现，已知合同直接使用 |
| 更新后仍找不到工具 | 实际安装制品与宿主发现状态 | 按宿主正式机制重新发现；不修改运行缓存 |
| Schema 通过但写入失败 | 权限、归属、CAS、业务前置 | 使用稳定错误码解决具体缺口 |
| 审批成功重放却报冲突 | 原键查找与 CAS 的顺序 | 授权后先回查原操作，再判断首次写入修订 |
| 提交超时 | 是否已获得原操作身份 | 保留原键恢复，不能换键重发 |
| 等待耗尽被显示为失败 | 观察期限与业务终态是否混用 | 返回当前状态并说明停止等待 |
| 批量结果看似成功但漏项 | item_id、逐项状态及未执行项 | 保留所有结果，不以 HTTP 状态概括 |
| 轮询拖慢页面 | 多处同对象请求、终态停止、可见性 | 范围化合并与修订读取，保留取消和错误 |
| 已开启浏览器仍无法连接 | 宿主服务和可用表面 | 记录连接故障，继续可独立完成的工具步骤 |

## 生成最小证据

记录精确制品、规范及合同修订、脱敏任务引用、预期/实际状态和最小复现步骤。把未执行项明确列出。不要附 Cookie、Token、数据库导出或模型私有推理。

如果状态未知，保留原操作上下文直到问题查明。诊断动作保持只读；任何新的写入都要重新判断适用授权。
