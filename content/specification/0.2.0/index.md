# AXI 0.2.0

**状态：草案。** 本版定义与传输无关的操作合同，以及可用于交换和测试的 JSON 表示。它不定义网络握手、RPC 路由或新的授权系统。

## 范围

核心覆盖发现、定位、执行、观察与恢复，并约束组件的集成生命周期。分页、批量和等待是可选能力；一旦声明支持，就必须满足相应章节要求。浏览器视觉能力只在任务需要时采用。CLI、MCP、Skills、插件与交互视图按原生合同协作，不要求全部采用。

| 层次 | 本版定义 | 保持在采用方的内容 |
| --- | --- | --- |
| 语义 | 上下文、副作用、状态、错误、恢复 | 领域流程、质量判据、商业规则 |
| JSON 表示 | catalog、action、result、page、batch | 业务输入和输出 Schema |
| 绑定 | CLI、MCP、网页的映射要求 | 既有协议版本、地址、认证实现 |
| 验证 | 静态、行为、任务三类证据 | 目标宿主、数据、性能预算 |

## 规范用语

本文中的**必须（MUST）**、**不得（MUST NOT）**、**应当（SHOULD）**、**不应（SHOULD NOT）**与**可以（MAY）**具有 BCP 14 的要求强度；仅这些明确标示的用语构成要求。应当项允许有理由的偏离，采用清单需记录理由与影响。

带 `AXI-…` 编号的段落是可追踪要求。构建从这些段落生成[要求索引](../../requirements.json)，不另维护一份规则副本。

**AXI-CORE-001**：实现必须声明精确规范版本、提供方标识、所覆盖的核心任务和绑定；不得仅以“支持 AXI”代替声明范围。

**AXI-CORE-002**：人类入口与 Agent 入口必须使用同一领域权限、修订、副作用和事实源；接入层不得直接绕过业务校验写入领域存储。

## 数据合同与优先级

[JSON Schema](../../schemas/0.2.0/axi.schema.json)是字段、类型、必填、枚举和组合结构的权威定义。各章节是行为、顺序、授权、状态和恢复语义的权威定义。示例是说明，不扩大合同。两者发生矛盾时应视为规范缺陷，不能宣称通过符合性验证。

JSON Schema 可验证回执形状，不能证明权限真实、幂等持久化或任务质量。验证层次见[符合性](../../verification.md)。
