# 采用清单

采用方在自己的仓库维护本清单，记录产品事实与证据，不把业务实现路径加入通用规范。以下模板可直接复制；空项必须填写“不适用及理由”或“未验证”，不能默认为通过。

## 声明

```yaml
spec_version: "0.2.1"
spec_status: draft
provider_id: "<提供方稳定标识>"
artifact_version: "<实际制品版本>"
artifact_sha256: "<实际摘要>"
bindings: []
tasks: []
optional_features: []
runtime_modes: []
unsupported: []
evidence: []
```

规范版本不能替代制品摘要，网页、插件与 CLI 独立发布时分别记录。声明不包含真实凭据或当前用户数据。以上是采用方清单，不是AXI五种JSON交换文档；运行模式不作为未定义核心字段塞进动作或结果。

## 任务矩阵

| 字段 | 填写内容 |
| --- | --- |
| 任务及完成判据 | 用户目标、结果范围、质量判据 |
| 发现 | 目录、精确合同、方法、修订与失效 |
| 定位 | 范围、对象、歧义、深链与旧上下文清理 |
| 执行 | 副作用、输入、授权、CAS、预算与幂等 |
| 观察 | 终态、产物、质量和费用的独立结论 |
| 恢复 | 原键、输入摘要、保留期与人工核对 |
| 可选能力 | 分页、批量、等待、取消与页面工具 |
| 降级 | 无插件、无浏览器、断线、失权与接管 |
| 性能 | 每入口的冷/热预算、首次反馈/可用/完整结果、原始样本、成功率和尾部延迟 |
| 发布核验 | 远端制品、新会话发现、目标环境任务 |
| 运行模式 | 页面/文件/执行/状态归属、身份与网络依赖、安装期与运行期分别验证 |
| 本地工作区 | 目录选择、OS默认根、源文件/内部状态/索引分工、外部编辑、搬移和一致备份 |
| 数据保留 | 临时取得期限、配额、引用/unknown保护、删除确认与费用审计分离 |
| 渐进使用与选择 | 首个业务结果、默认值、按需连接、宿主原生选择/能力协商、拒绝/取消/无界面降级 |
| 宿主扩展 | 普通网页、MCP App与本地客户端分别记录API和权限；WebMCP、标注、原生面板/文件/消息逐项验收 |

Codex采用方可使用[逐接口验证矩阵](../ecosystem/codex/verification.md)；其他宿主在各自目录维护独立证据，不继承Codex结论。

## 要求映射

构建生成的[要求索引](../requirements.json)提供规范编号、来源和原文。采用方为每个适用编号填写实现位置、正例、负例、证据时间、制品摘要和结论。

| 要求编号 | 实现/测试 | 证据 | 结论 |
| --- | --- | --- | --- |
| AXI-CORE-001 | `<范围声明位置>` | `<实际制品摘要>` | 未验证 |
| AXI-REC-001 | `<同键重放和并发测试>` | `<真实运行记录>` | 未验证 |
| AXI-CANCEL-001 | `<取消范围测试或不适用理由>` | `<记录>` | 未验证 |

## 声明写法

可写“该制品在指定宿主完成任务 A/B 的合同与行为验证，页面工具未验证”。不要写“全面符合 AXI”却不提供任务、版本与范围。单个 Schema 通过、截图或排队回执只能证明对应层次，见[符合性](../verification.md)。
