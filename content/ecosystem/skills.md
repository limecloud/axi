# Skills 方法层

Skill 把“使用者的目标”连接到工具的正确组合。OpenAI 官方文档明确区分：MCP Server 提供实时信息、鉴权和受控动作，Skill 提供工作流、例子和资源；仅需方法资源时，Skill 也可以独立工作。

## 组织方法

```text
document-review/
└── SKILL.md
```

一个简单方法可以只有入口文件，不必为了形式添加脚本与多个引用目录。复杂流程再按条件拆分参考，避免所有模式每次一起加载。

| 位置 | 内容 | 设计目的 |
| --- | --- | --- |
| name / description | 能做什么、什么目标应触发 | 便宜且准确地发现方法 |
| 方法正文 | 路由、关键不变量、缺项、恢复与输出 | 改善执行决定 |
| 可选 references | 仅部分模式需要的细节 | 按需披露 |
| 可选 scripts | 稳定、可重复的确定性逻辑 | 减少模型循环 |
| 动态工具合同 | 参数、边界、副作用和状态 | 由实际提供方维护，避免复制漂移 |

## 激活和授权

方法元数据先进入发现范围；完整正文在匹配目标或用户主动调用时加载。宿主的具体发现机制不同，不把“某宿主会自动读文件”推广成跨宿主保证。

Skill 激活不表示已联网、已连接、已获权或可以发布。方法应尊重原意图，已有授权足够时执行；出现新决定时先准备可审核内容。外部方法同样不拥有提升权限的能力。

## 本仓库方法示例

[下载审批方法包](../downloads/document-review-skill.zip)。源码在仓库 `examples/review/skills/document-review/SKILL.md`，它使用当前已发现的 `documents.get`、`documents.decide` 与 `operations.get` 合同，不硬编码生产地址或复制全部参数。

这个方法演示唯一对象定位、固定修订、原键恢复和结果范围。它没有把 Skill 安装到当前用户配置，也没有声明在所有宿主已通过模型行为测试。

## 测试与迭代

测试显式调用、自然目标触发、同名对象、缺连接、修订改变、超时、撤权和无视觉能力。方法检查可验证元数据与引用，但真正的激活准确率和决策质量必须在目标宿主测量。

工具合同变化时核对引用动作与恢复规则；没有方法语义变化不必每次重写 Skill。Skills、目录、Schema 和运行制品的发布关系见[Skills 与交付](../discovery.md)。
