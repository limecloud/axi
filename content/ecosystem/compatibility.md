# 兼容性矩阵

“有接入文档”“有参考代码”“通过指定宿主测试”和“已发布可安装制品”是不同状态。AXI 不根据某个宿主支持 MCP 就推断它支持所有插件、Skills 或 MCP Apps。

## 采用方应记录的矩阵

每个目标宿主填写精确版本、平台、分发渠道、连接方式、身份模式、工具/资源支持、Skill 发现、UI 扩展、升级机制、降级及证据。不能只写一个“兼容”勾号。

同一个宿主在 Web、桌面、CLI 和工作区管理模式下可能有不同能力。原生工具、页面工具和浏览器控制权限也要分开记录。

补充记录人类TTY、非TTY/机器模式、项目目录选择、loopback可达性、文件权限、运行期网络和离线依赖。CLI完整核心路径不能由“可打开网页”代替。新本地工作区章节是设计指南，本仓库没有因此增加媒体编辑器或本地Web参考实现。

## 能力协商与降级

先使用载体现有的能力发现机制。没有 UI 扩展就返回结构化结果；没有页面工具就使用语义界面；没有浏览器就继续直接工具步骤，视觉步骤按需接管。某项缺失会破坏任务正确性时，应明确阻塞，不用降级伪装成功。

AXI 版本与宿主协议版本独立。当前 MCP 官方规范版本和插件文档格式见[参考来源](../references.md)，但运行时仍以采用方冻结的版本为准。
